# T1' — 服务器：令牌一对一配对模型

## 需求来源

- **[用户裁定]** 严格一对一配对：一个 MCP 令牌 ↔ 一个桥令牌，成对签发、成对生效、成对吊销；同一用户名可持有多对（byron2 = byron 的第二台机）。
- **[用户裁定]** 否决"设备绑定"方案：MCP 不绑定设备，配对本身就是路由依据。
- **[事实]** 现模型按用户名兜底路由：MCP 令牌认证后找"该用户名在线的桥"，同用户多台桥/令牌交叉时会打到错误目标。
- **[AI 判定]** 吊销 byron 的临时 MCP 令牌 lfs-mcp-1847（破坏一对一；执行时由中枢经 admin 接口操作，不在本任务书范围）。

## 目标

MCP 工具调用**只路由到配对桥令牌注册的那台桥**；配对桥不在线时返回明确错误，不做任何兜底。

## 范围（只改 server/）

1. `tokens.py`：.env 解析改为**配对模型**——现有两行式（`byron.bridge=xxx` / `byron.mcp=yyy`）映射为一对；支持一个用户名多对（如 `byron2.bridge` / `byron2.mcp` 天然就是第二对）。对内互相绑定：mcp 令牌 → 配对 bridge 令牌标识。
2. 会话注册：桥用桥令牌认证时，记录其所属**配对标识**（不是设备绑定——只是"这个桥由哪对令牌的桥令牌注册"）。
3. MCP 调用路由（app.py）：MCP 令牌认证 → 找其配对桥令牌的在线会话 → 精确下发；配对桥不在线 → 返回明确错误 `"pair-bridge-offline"`（消息文案：配对的桥未在线）。
4. admin 接口：`GET /admin/tokens` 与 `/admin/sessions` 显示配对关系（哪对是一对、配对桥是否在线）。
5. 兼容性：现有 .env 不改格式即可工作；byron 名下 2 个 MCP 令牌中，未配对的（lfs-mcp-1847）在中枢吊销，代码不需要特判。

## 禁止事项

- 不做设备标识、设备绑定、心跳、UI；
- 不动 bridge/、desktop/；
- 不改 .env 实际文件（测试用注入环境变量）；
- 不碰 VERSION 文件（中枢统一升版）。

## 验收标准

- pytest 全绿（含新增：配对路由命中 / 配对桥离线报错 / 多对并存 / 未配对 MCP 令牌行为）；
- 现有 91 个测试零回归；
- admin/sessions 输出能看到配对关系（报告中附实际 JSON）。

## 环境

GOROOT 无关（Python）；本地 Docker 可起测试适配器；禁止连生产。
