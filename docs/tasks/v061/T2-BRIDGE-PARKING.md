# T2' — 桥：被接管停泊（不自动抢回）

## 需求来源

- **[用户裁定]** 后连接的设备永久在线；被顶掉的设备必须停在"已被接管"状态，**只有人点「连接」才允许抢回**，不允许自动重连抢回。
- **[事实]** 两机同用 byron 桥令牌时，服务器以 close code=4000（"replaced by reconnect"）踢旧连接，旧桥 1 秒后自动重连，形成每 2~4 秒一轮的乒乓战（docker logs 12:43~12:48 实录）。
- **[AI 判定]** 实现方式：桥识别服务器关闭码 4000 → 进入"停泊"状态（conn_state=`parked`），终止自动重连循环；其他断开原因（网络闪断等）行为不变。

## 目标

同令牌在第二台机器连接时，第一台机器自动停泊；恢复只由用户手动触发。

## 范围（只改根模块 Go 代码 + protocol 相关）

1. `client.go`：Run 循环中识别 websocket close code 4000 → 置停泊标志，退出重连循环（不再定时重连）；非 4000 的断开维持现有退避重连。
2. 状态上报：StatusDetail/conn_state 新增 `parked`；附原因字段（如 `superseded`）。
3. 恢复路径：用户手动连接（现有手动 Connect 逻辑）或保存配置 → 清停泊标志重新连接。
4. 测试：模拟服务器 4000 关闭 → 断言不再重连、状态为 parked；普通断开 → 断言仍自动重连（反向用例）。

## 禁止事项

- 不改桌面 UI（T3' 负责）、不改 server/；
- 不做"停泊超时自动恢复"之类的自作主张行为；
- 不碰 VERSION 文件。

## 验收标准

- `go build ./... && go vet ./... && go test ./... -count=1` 全绿（根模块）；
- 新增用例：4000→parked 不重连；普通断开→照常重连；
- 报告附 git diff 摘要与测试原文。
