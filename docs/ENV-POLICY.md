# 环境隔离与生产操作规范

> 制定：2026-09-30。起因：当天桌面客户端 M3 复验时，执行侧默认连生产服务器做验证、读取生产 .env 凭证，事后未报备，被定为事故。本规范为防再犯的制度化约束，对 AI 执行侧与人工运维同等生效。

## 一、环境分层（铁律）

| 环境 | 形态 | 用途 | 访问规则 |
|---|---|---|---|
| **dev** | 本地 build + 本地起进程/单测 | 日常开发自测 | 自由 |
| **staging** | 独立 compose（见 `docker-compose.staging.yml`），端口 18080/18445，独立令牌、独立卷、独立网络，与生产零共享 | 一切验证：桥连接、e2e、升级演练、客户端复验、CI 产物验收 | 自由 |
| **prod** | 生产 compose（8445 公网 TLS），真实用户在用 | 只服务真实用户 | **先报备、等批准、后操作** |

**核心原则：有真实用户（或即将有）之后，生产不是测试靶子。任何"验证一下"的冲动默认落 staging。**

## 二、生产操作分级

### 需事前报备并等批准（写在消息里，等明确"同意/批准"）
- 连接生产做任何验证（含只读查 sessions、healthz）
- 读取/使用生产任何凭证（.env 里的 admin token、桥令牌、MCP 令牌）
- 升级 Docker 镜像、改生产 compose、重启/停止生产容器
- 改生产配置、动生产数据（含 .env、令牌签发/吊销）
- 任何会改变生产对外行为或会话表的动作

### 事后必须汇报（回执制）
- 获批操作执行完毕后，附结果回执：做了什么、结果、副作用

### 免批区
- dev/staging 内一切动作（进度播报带环境标注即可）
- 纯本地文件读写、代码编辑、git 提交

## 三、预告-回执制（执行侧运行纪律）

1. **动作前预告**：凡网络连接、凭证读取、进程启停、环境写操作、文件删除/移动/覆盖，动手前先说一句「接下来我要 XXX（环境：X）」。
2. **汇报格式带环境字段**：`进度%｜环境：dev/staging/prod｜已完成｜下一步`。prod 字样出现即用户干预点。
3. **每轮回执**：汇报末尾固定「本轮环境动作」——连了哪个环境、动了什么、有无凭证使用。预告可能漏，回执不漏；回执是用户的审计窗口。
4. **高危不打包**：跨环境多步操作拆开逐项报批，不许合并成一个"下一步"糊过去。

## 四、staging 环境

- 文件：本目录 `docker-compose.staging.yml`
- 与生产差异：端口 18080(plain)/18445(TLS)、独立容器名 `localoctop-server-staging`、独立卷 `localoctop-audit-staging`、独立网络、令牌走 `.env.staging`（不入 git）、**自签证书**（不占生产 LE 证书）
- 启动：见 compose 头部注释
- 客户端验证时用独立测试配置（不碰 `%APPDATA%\localoctop\config.json` 真实配置）
- **staging 数据随时可清**：`docker compose -f docker-compose.staging.yml down -v`
