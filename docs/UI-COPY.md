# UI 文案规范（UI-COPY）

> 0.6.0 起生效。所有面向用户的界面文案（主窗口、托盘、安装器、报错提示）必须遵守本规范。
> 核心原则一句话：**状态说结果，不说机制；每条提示都告诉用户"下一步该干嘛"。**

## 三条原则

1. **说结果，不说机制**：不向用户解释实现原理（心跳、协议、超时、重试计数）。用户只关心"云端 AI 现在能不能访问我的文件"。
2. **指标可行动**：状态卡只展示用户能理解、能据此行动的信息（目录、最近操作、服务器地址）。工程指标（尝试次数、累计重连、客户端 ID、pong 时间）一律不上界面。
3. **错误带动作**：每条错误/异常文案必须包含"现在系统在做什么 + 用户可以做什么"。原始技术报错放鼠标悬浮提示（title），不占主文案。

## 术语对照表（强制）

| 禁用（界面不得出现） | 统一用词 | 说明 |
|---|---|---|
| 心跳 / pong / ping | 不出现；需要表达时用"连接状态/连接不稳定" | 实现机制，用户无需知道 |
| 审计 / 审计日志 | 操作记录 | 同一事物，界面与文档统一叫"操作记录" |
| 重连中（第 N 次） | 重连中… | 次数是工程指标，对用户是噪音 |
| 客户端 ID | 不上界面 | 排障时看日志文件 |
| 当前尝试 / 累计重连 | 不上界面 | 同上 |
| 桥核心 / 主仓 / bridge.exe | 不出现；说"命令行版本"或干脆不说 | 开发行话 |
| 断开桥 | 停止文件访问 / 已断开 | 用户语言 |
| idle 超时 / 4408 / WS 控制帧 | 严禁出现 | 纯协议细节 |

## 五态标准文案（主窗口状态卡）

| 状态 | 大字 | 副文案 | 角标 |
|---|---|---|---|
| 已连接 | 已连接 | 云端 AI 可正常访问白名单目录 | 已连接 |
| 连接不稳（已连但检测异常） | 连接不稳定 | 与服务器的联系时断时续，正在自动恢复… | 连接不稳定 |
| 连接中 | 连接中… | 正在与服务器建立连接… | 连接中 |
| 重连中 | 重连中… | 连接中断，正在自动重连；若长时间未恢复，请检查网络。 | 重连中 |
| 已断开（手动） | 已断开 | 已断开 · 云端 AI 暂时无法访问你的文件，点「连接」恢复。 | 已断开 |
| 未配置 | 未配置 | 填写服务器地址与令牌并保存后开始连接。 | 未配置 |

## 托盘

- 退出菜单：「退出」→ 悬浮提示「退出并停止文件访问」。
- 状态行：已连接 / 连接中… / 重连中… / 已断开 / 未配置（与主窗口同词）。

## 落地位置

- 主窗口：`desktop/frontend/index.html`、`desktop/frontend/src/main.js`
- 托盘：`desktop/internal/tray/tray.go`（TrayLabel / SetStatus 的文案）
- 新增界面文案时，先查本表；拿不准就用"结果 + 下一步动作"句式自检。
