# REPO-GOVERNANCE — 仓库治理规范（三层）

> 来源：[用户裁定 2026-09-30] 做好本软件/本仓的软件管理，覆盖：① 云端 Git 仓与迭代规范；② 本地目录规范；③ 沟通互动产生的版本与过程文件规范。目标：每个文件有唯一归属、明确生命周期，杜绝屎山堆积。

---

## 一、云端 Git 仓（GitHub）

### 1.1 仓清单（本产品只允许这 3 个，新增仓必须先报备批准）

| 仓库 | 可见性 | 职责 |
|---|---|---|
| `byronz1z/localoctop` | 公开 | **唯一开发真源**：全部代码+文档+发版 |
| `byronz1z/localoctop-desktop` | 公开·已归档 | 旧桌面仓，只读历史，禁止任何写入 |
| `byronz1z/ZBSwork-OCTOP-service` | 私有 | ops 部署仓：compose、.env 模板、证书脚本（敏感件永不进公开仓） |

### 1.2 迭代流程（每版本固定走这条链，不得跳步）

```
需求确认（用户裁定，标来源）→ 中枢写任务书（docs/tasks/v<版本>/）
→ 用户批准任务书 → AI 写码（质量门全绿）→ 中枢复验
→ 合入 main 推送 → 用户验收 → 改 VERSION + 打 tag
→ CI 双管线出包（同一 Release）→ 产物独立复核 → 生产部署（报备获批）
```

### 1.3 分支与 tag

- `main` = 唯一主干，随时可发布；批量开发用 `feature/v<版本>` 分支，复验后合入；
- tag 仅在发版时打，命名 `v<版本>`（单 tag 制，见 VERSION-POLICY.md）；
- 发版后下载页只留最新 Release（tag 保留回溯）。

## 二、本地目录规范

| 本地路径 | 对应 | 规则 |
|---|---|---|
| `D:/SelfHosted/localoctop/` | 主仓工作副本 | 与 GitHub 同步；本地实验性改动不 commit 就不 push |
| `D:/SelfHosted/ZBSwork-OCTOP-service/` | ops 仓工作副本 | 只由中枢操作（部署动作） |
| `D:/SelfHosted/localoctop-server/` | **生产数据目录，非 git** | .env/证书/审计日志；永不入任何仓；操作前报备 |
| `D:/tmp/` | 一切临时文件的唯一去处 | 构建中间物、探测脚本、下载验证；任务结束即清理 |
| 其他位置 | **禁止** | 项目相关文件不得散落仓外任何地方 |

## 三、仓内文件归属（每个位置只放一类东西）

| 位置 | 放什么 | 禁止 |
|---|---|---|
| `/`（根） | 桥核心 Go 代码 + 治理文件（README、CHANGELOG、VERSIONS、VERSION、AGENTS、workflow） | 业务代码外的杂物 |
| `server/` | 服务器适配器（Python）+ 其 Dockerfile/测试 | 桌面/桥代码 |
| `desktop/` | 桌面端（Wails/Go/Svelte） | 服务器代码 |
| `ops/` | 部署参考描述（真实部署细节在私有 ops 仓） | .env、token、证书 |
| `docs/` | 规范文档（ENV-POLICY、VERSION-POLICY、DECISIONS、UI-COPY、本文件） | 临时笔记 |
| `docs/tasks/v<版本>/` | 该版本任务书，格式 `T<编号>-<主题>.md` | 无来源标注的任务书 |
| `build/bin`、`dist`、`__pycache__`、`node_modules` | 构建产物 | **永不 commit**（.gitignore 兜底） |
| 归档 | 过期任务书封存于原版本目录，不删除 | 移动历史文件需在 commit message 说明 |

## 四、过程文件规范（你我沟通产生的记录）

| 文件类型 | 位置 | 命名/格式 | 生命周期 |
|---|---|---|---|
| 决策台账 | `docs/DECISIONS.md` | 三类标记：[用户裁定]/[AI 判定]/[事实] | 只增不删，被否决项保留改状态 |
| 任务书 | `docs/tasks/v<版本>/T<编号>-<主题>.md` | 开头必须有「需求来源」段（逐条标注三类标记），无标注不得开发 | 版本发布后封存 |
| 版本对照 | `VERSIONS.md` | 三组件版本 + tag + 日期 | 每次发版追加一行 |
| 变更日志 | `CHANGELOG.md` | 按版本分节，写用户可感知的变化 | 随发版更新 |
| 工作日志 | 本地 `.workbuddy/memory/YYYY-MM-DD.md`（不进公开仓） | 按日追加 | 定期（30 天+）提炼进 DECISIONS 后清理 |
| 会话汇报 | 对话内，不落盘 | `进度%｜环境｜已完成｜下一步` + 环境回执 + **本轮决策点**（AI 自定项单独列出） | 每轮必须 |

## 五、防屎山三条铁律

1. **先归属后落盘**：任何新文件产生前，先在上表找到它的位置；找不到位置=不该存在；
2. **先批准后提交**：规范类、需求类文档必须用户批准后才 commit；AI 判定类文档（如 UI 文案表）也要在汇报中显性列出；
3. **每版本一次清点**：发版前盘点仓内是否有超期未归档任务书、未登记决策、残留临时文件，清完才打 tag。
